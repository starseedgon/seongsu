# 고객 주요 질문 제안 답변

> 작성 기준: `question.jpg`의 10개 질문에 대한 킥오프 단계의 제안 답변입니다. 실제 가능 범위와 견적은 기존 시스템·운영사 API, 현장 네트워크, 장비 모델을 확인한 뒤 확정해야 합니다.

## 1. 통합 구축 역량

가능합니다. 회의실, 업무차량, 리프레시룸, 방문 주차, 식음료를 **공통 사용자·예약·자원·토큰·알림 모델**로 통합하고, 기능별 외부 시스템은 어댑터로 연결하는 구성을 제안합니다. 임직원은 하나의 웹/모바일 웹에서 검색·예약·이용·취소를 처리하고 관리자는 운영 현황과 장애, 이용 분석을 통합 화면에서 확인합니다.

단, 식음료의 주문·결제와 주차권 발급은 해당 운영사 API 제공 여부에 따라 자체 화면 통합, 딥링크, 정산 파일 연계 중 구현 수준이 달라집니다.

## 2. 토큰 운영 체계

구현 가능합니다. 임직원·부서 단위 지갑, 월 정기 배분, 관리자 수동 조정, 시설·시간대·공간별 요율, 예약 시 선차감, 취소 시 환불, 노쇼 패널티, 이월·소멸 정책을 규칙으로 관리할 수 있습니다. 모든 증감은 원장 방식으로 기록해 잔액과 변경 근거를 추적합니다.

프로토타입에는 부서별 배분·잔액·사용량, 예약 시 차감, 취소 시 환불, 추가 배분 기능이 구현되어 있습니다.

## 3. 기존 사내 시스템 연동

다음 표준 방식을 우선 제안합니다.

| 대상 | 권장 방식 | 별도 개발 가능성이 높은 부분 |
|---|---|---|
| 그룹웨어·캘린더 | REST API, Webhook, 필요 시 iCalendar | 예약 양방향 충돌 처리, 반복 일정, 권한 매핑 |
| 인사·조직 | SCIM 2.0 또는 증분 REST/배치 | 사내 조직코드·겸직·휴직 규칙 매핑 |
| SSO | OpenID Connect 또는 SAML 2.0 | 사내 IdP 등록, 역할·클레임 매핑 |
| 사원증·출입통제 | 제조사 API/SDK, 필요 시 OSDP 게이트웨이 | 출입권한 발급·회수, 카드번호 토큰화, 현장 장비 제어 |

외부 API가 없거나 폐쇄망 전용일 경우 제조사 미들웨어 또는 현장 게이트웨이 개발이 필요합니다.

## 4. 회의실 운영 자동화

예약, 입실 확인, 미사용 예약 자동 취소, 종료 후 자동 반납, 도어 사이니지 표시, 화상회의 장비 연동까지 구현할 수 있습니다. 권장 흐름은 다음과 같습니다.

1. 캘린더 예약 생성 및 공간 충돌 확인
2. 시작 전 사이니지·참석자 알림
3. 사원증/QR 또는 재실 센서로 입실 확인
4. 기준 시간 내 미입실이면 알림 후 자동 취소
5. 이용 종료 시 공간·출입권한·장비 세션 자동 해제

Teams Rooms/Zoom Rooms 및 사이니지는 각 제품의 관리 API와 장비 제어 범위를 확인해야 합니다. 안전·개인정보 이슈 때문에 단일 재실 센서가 아닌 예약·출입·재실 이벤트의 복합 판정을 권장합니다.

## 5. 업무차량·리프레시룸 관리

가능합니다. 업무차량은 예약, 승인/배차, 차량·운전자 자격 확인, 스마트키 대여·반납, 운행 전후 체크리스트, 주행기록 연계를 구성할 수 있습니다. 리프레시룸은 예약, 일회성 출입권한, 재실 확인, 이용 종료, 청소/점검 상태를 통합 관리합니다.

차량 위치·주행거리·충전량 자동 수집은 차량 제조사/관제 단말 API 또는 별도 OBD·텔레매틱스 장비가 필요합니다.

## 6. 주차·식음료 시스템 연동

연동 가능합니다. 주차는 차량번호 사전등록, 방문 주차면 배정, 입출차 이벤트, 할인권/정산을 주차관제 API로 연결합니다. 식음료는 상품·재고·주문·승인 결과를 운영사 API로 연동하고, 사내 토큰과 현금성 결제는 회계상 분리 정산하는 방식을 권장합니다.

외부 업체 협조 필수 항목은 API/SDK 명세, 테스트 계정·샌드박스, 네트워크 허용 목록, 이벤트 전송 방식, 장애 코드, 정산·취소·부분환불 규칙, 개인정보 처리 책임, 기술지원 SLA입니다.

## 7. 방문객 및 출입보안

구현 가능합니다. 임직원이 방문객을 사전등록하면 제한 시간·구역이 포함된 임시 QR을 발급하고, 2.5층 라운지 리더에서 인증하면 담당자에게 알림을 보냅니다. 입실·퇴실 이벤트와 만료·회수 상태는 출입통제 시스템과 동기화합니다.

운영 환경에서는 QR 원문에 개인정보를 넣지 않고 짧은 수명의 서명 토큰 또는 서버 조회용 난수를 사용해야 합니다. 스크린샷 재사용 방지, 본인 확인 수준, 동반 방문객 처리, 비상시 출입 원칙을 고객 보안정책과 맞춰야 합니다.

## 8. 데이터·AI 분석

가능합니다. 예약·실사용·취소/노쇼·토큰·출입·센서 이벤트를 공통 이벤트 모델로 수집해 시설별 활용도, 피크 시간, 평균 이용시간, 공급 부족, 장비 가동률을 분석합니다. 원본 데이터는 권한과 비식별 정책에 따라 CSV/Parquet/API로 제공할 수 있습니다.

외부 AI 연계는 비식별·집계 데이터를 우선 사용하고, 목적·보존기간·처리 위치·재학습 사용 여부를 승인받은 뒤 전용 엔드포인트 또는 사내 AI 게이트웨이로 연결합니다. 프로토타입의 AI 제안은 샘플 규칙 기반 결과이며 실제 모델 판단이 아닙니다.

## 9. 구축 범위 및 비용

필수 하드웨어 후보는 현장 조사 후 확정합니다. 일반적으로 재실/환경 센서, 도어 사이니지, QR 리더 또는 출입 게이트 연동 모듈, 차량 키 보관함, IoT 게이트웨이, 관리자·라운지 단말, 필요 시 네트워크 증설이 포함됩니다.

견적은 아래 항목으로 분리 제안하는 것이 적절합니다.

- 소프트웨어: UX, 포털, 관리자, 백엔드, 연동 어댑터, 데이터/분석, 시험
- 장비: 센서·리더·사이니지·게이트웨이·키 보관함·설치 공사
- 라이선스: 클라우드, 장비 관리, 메시징, 지도/알림, 외부 제품
- 구축 서비스: PM, 설계, 현장 설정, 데이터 이관, 교육, 안정화
- 연간 운영: 유지보수, 모니터링, 장애대응, 보안 패치, 라이선스 갱신

현재 정보만으로 금액을 확정하면 연동과 현장 공사 리스크가 견적에 과도하게 반영됩니다. 요구사항·API·도면·장비 확정 후 산출해야 합니다.

## 10. 구축 일정 및 책임 범위

2027년 5월 입주 기준으로 **단계적 구축과 최소 6~8주의 통합시험·안정화 기간**을 확보하면 추진 가능합니다. 권장 일정은 다음과 같습니다.

- 2026년 10~12월: 요구사항, 운영정책, 현장·외부 API 조사, 기본설계
- 2027년 1~2월: 핵심 플랫폼·연동 어댑터 개발, 장비 발주
- 2027년 3월: 현장 설치, 단위시험, 데이터 이관
- 2027년 4월: 통합시험, 보안점검, 사용자 인수시험, 교육
- 2027년 5월: 입주 지원, 집중 모니터링, 안정화

주사업자가 통합 PM, 공통 플랫폼, 연동 관리, 통합시험, 1차 장애 접수와 원인 분류를 책임지고, 장비·외부 솔루션사는 제품 설치·API·제품 결함·현장 기술지원 책임을 맡는 RACI를 계약에 명시하는 방식을 권장합니다. 최종 일정은 건축·인테리어·네트워크 공정과 외부사 API 제공 시점을 함께 기준선으로 관리해야 합니다.
